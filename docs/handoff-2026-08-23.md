## Implemented architecture and compatibility

- `zgrep` defaults to BRE; `zegrep` selects ERE from `argv[0]`.
- `-G`, `-E`, `-F` and `-P` are implemented.
- Non-literal BRE/ERE and PCRE use PCRE2 JIT through `src/pcre2_shim.c`.
- Literal search uses SIMD plus Boyer-Moore-Horspool-style skipping.
- Simple ERE literal alternations have a dedicated SIMD path.
- Required-literal extraction prefilters eligible ERE patterns.
- Large regular files are memory-mapped; files up to 64 KiB use a stack buffer.
- Literal stdin/file output is streaming and bounded by the longest record.
- Literal, literal-alternation and PCRE2 counts are parallel on large buffers.
- PCRE2 parallel paths use one mutable match-data object per worker.
- Large literal and literal-alternation output uses ordered, line-aligned,
  parallel discovery. Literal `-o` uses the same path.
- Parallel output metadata is capped at 64 Ki selected spans per chunk (at most
  about 25 MiB over 16 chunks); the code falls back before emitting anything
  when the cap is exceeded.
- Recursive `-l` and `-L` scans are parallel and retain deterministic traversal
  order. Regex recursion now creates one PCRE2 worker per thread.
- `-r` and `-R` implement symlink-loop diagnostics and `-s` suppression.
- Ordered GNU-style `--include`, `--exclude`, `--exclude-from` and
  `--exclude-dir` filters are implemented, including POSIX glob classes.
- `-z`/`--null-data` is implemented across SIMD paths, parallel counts, PCRE2,
  context, stdin, offsets and output. PCRE2 DOTALL is enabled so `.` matches an
  embedded newline within a NUL-delimited record, matching GNU grep.
- `-Z`/`--null` independently NUL-terminates printed filenames, including
  normal, count, context and recursive `-l`/`-L` output.
- Binary modes `binary`, `text` (`-a`) and `without-match` (`-I`) are covered.
- Output controls include `-v`, `-c`, `-m`, `-n`, `-b`, `-o`, `-w`, `-x`,
  `-H`, `-h`, `-q`, `-s`, `-l`, `-L`, labels and context `-A/-B/-C`.
- Multiple `-e` patterns, pattern files, newline-separated pattern arguments,
  missing final newlines and empty pattern-file cases are covered.

## Ripgrep reuse completed

The external harness cannot execute a grep-compatible binary unchanged because
many options and default traversal rules are ripgrep-specific. Portable ideas
were adapted instead, with attribution comments in `tests/differential.sh`.

Reused regression families include:

- maximum count and zero maximum count;
- duplicate and empty pattern files;
- binary/NUL behavior;
- context grouping and partial context overrides;
- NUL-data empty-record regression `f993`;
- NUL-data whole-record regression `r2658`;
- recursive filters and ordered include/exclude behavior;
- one-large-file and many-small-files benchmark families;
- literal, case-insensitive, word, alternation, required-literal and no-literal
  workloads.

Benchmark lanes now available:

```sh
bench/generate.sh /tmp/zgrep-bench.txt 3000000
ZGREP=./zig-out/bin/zgrep bench/run.sh /tmp/zgrep-bench.txt 20

bench/generate.sh /tmp/zgrep-bench-nul.dat 3000000 nul

ZGREP=./zig-out/bin/zgrep \

```

`run-tree.sh` now verifies and times literal, case-insensitive, word, multiple
literal and no-literal regex cases against both GNU grep and ripgrep.

## Remaining work

There is still substantial work for a production-quality, drop-in grep, but
not for proving the current performance core.

High priority:

1. Create the first Git commit after reviewing the all-untracked baseline.
2. Add CI for Zig 0.16, PCRE2 availability and the GNU differential lane.
3. Audit BRE/ERE edge semantics systematically against GNU grep, especially
   anchors, bracket expressions, backreferences, locale and invalid patterns.
4. Decide and document the intended locale/Unicode contract. Current literal
   case-folding and word checks are ASCII-oriented; PCRE2 behavior is separate.
5. Add permanent runtime coverage for the 64 MiB parallel-output threshold and
   the metadata-density fallback, beyond the small factored unit tests.
6. Stress memory limits, very long records, huge match counts, many roots,
   concurrent errors and interrupted output.
7. Add robust benchmark statistics (median/distribution, CPU governor/pinning,
   cold-cache versus warm-cache lanes) before claiming a release winner.

Compatibility gaps worth triaging:

- GNU directory/device controls (`-d`, `-D`) and special files;
- pattern input from `-f -` and interactions with stdin as search input;
- CRLF-specific behavior and locale-sensitive matching;
- actual color output (`--color` is currently accepted and ignored);
- line-buffered output, initial tabs and other less common GNU formatting flags;
- broader recursive normal-output parallelism (currently `-l/-L` are the
  dedicated many-file parallel path);
- Windows portability: the large-file path currently uses POSIX mmap.

Performance follow-ups:

- repeat the context benchmark because the 1–2 ms delta is within run noise;
- investigate parallel sparse regex output only if repeatable measurements show
  value (literal and literal-alternation output are already parallel);
- test the bounded-output fallback on deliberately dense matches;
- add larger real code trees in addition to the deterministic synthetic tree.
