## Work completed on 2026-08-24

### Real large-file stress lane

- Added `zig build test-stress -Doptimize=ReleaseFast`.
- `tests/stress.sh` generates newline- and NUL-delimited corpora larger than
  64 MiB and compares stdout, stderr and status exactly with GNU grep.
- It forces the production parallel-output threshold for sparse literal,
  literal `-o`, literal alternation and sparse required-literal regex output.
- It also forces deliberately dense output so the bounded metadata path must
  abandon parallel discovery before emitting and use the serial fallback.
- The scanner's internal output limits were factored so a unit test can force a
  zero-capacity metadata fallback and prove that no partial output is emitted.

### Sparse required-literal regex acceleration

- Parallel regex count workers now use the extracted required literal to jump
  directly between candidate records on sparse inputs.
- PCRE2 is invoked at most once per candidate record; invert count derives its
  result from the total record count.
- Sparse required-literal normal output now uses the same ordered, line-aligned,
  bounded parallel discovery model as literals and literal alternations.
- Each output chunk owns a PCRE2 worker/match-data instance; mutable PCRE2 state
  is not shared between threads.
- Regex `-o` deliberately remains on the existing serial path.
- Newline and NUL record modes are both covered by the large stress lane.

### Documentation

- README architecture now mentions sparse regex count/output acceleration.
- README documents the optional >64 MiB stress command.

## What remains

### Priority 1 — semantic compatibility

Build a deterministic GNU differential matrix, followed by a seeded fuzz lane,
for BRE/ERE semantics:

- anchors and empty matches;
- bracket expressions and POSIX classes;
- escaping, repetitions and alternation;
- BRE backreferences;
- invalid patterns and exit diagnostics;
- multiple `-e` patterns and pattern-file edge cases;
- CRLF and missing-final-delimiter inputs.

Then decide and document the locale/Unicode contract. Literal case folding and
word classification are currently ASCII-oriented while PCRE2 behavior is a
separate path.

### Priority 2 — missing GNU surfaces

- `-f -` and the interaction between pattern stdin and searched stdin;
- directory/device controls (`-d`, `-D`) and special files;
- actual color output (`--color` is accepted but ignored);
- line buffering, initial tabs and less common formatting flags;
- broader normal recursive-output parallelism;
- POSIX mmap replacement or abstraction for Windows portability.

### Priority 3 — hardening and release hygiene

- Very long records, huge match counts, many roots, concurrent errors, broken
  pipes and interrupted output.
- Add CI for Zig 0.16, PCRE2 and GNU differential/stress lanes.
- Review the all-untracked repository and create the first baseline commit.
- Add robust benchmark statistics and larger real-code corpora.

## Recommended first task tomorrow

Start with a read-only BRE/ERE behavior inventory against GNU grep, then add a
deterministic differential script for the highest-risk semantic cases. This
offers more value now than optimizing the current synthetic matrix further,
because zgrep already leads every row in that matrix and semantic drift is the
larger release risk.

After that, implement `-f -` stdin ownership rules or define the locale/Unicode
contract, depending on what the audit exposes.
