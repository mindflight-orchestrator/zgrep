# zgr v0.3 — comparative benchmark

[English](benchmark-v0.3.md) | [Français](benchmark-v0.3.fr.md)

Measurement captured on 2026-08-28 at 11:29 CEST on Linux 6.8.0 x86_64,
with an Intel Core i9-13900KF (32 logical CPUs), Zig 0.16.0, PCRE2 10.42,
GNU grep 3.11 and ripgrep 15.2.0. The deterministic corpus was generated by
`bench/generate.sh` with 1,000,000 records: 93,789,827 bytes and SHA-256
`da9fd9c2df9698ffcbeac1693c0fdf72b9357ff50fc0234c4e1d1f3f13797a3b`.

## Compared artifacts

- zgr v0.3, tag `8076821`:
  `b72bbc31d602cc270e70ae2ea5f4326688049642c081d5642a938c6030f54dcb`;
- zgrep v0.2, tag `1a2616d`:
  `a8b945c0aa73fce524f594a97da2e5ff83cbf5dc6459192b5ec422e17f31ee66`;
- GNU grep 3.11;
- ripgrep 15.2.0, revision `e89fff89ac`.

Both project binaries were built from their exact tags with
`zig build -Doptimize=ReleaseFast`.

## Method

- warm page cache, `LC_ALL=C`, `taskset -c 0-15`;
- 9 batches of 5 runs per tool and workload;
- tool order rotated inside every batch;
- median reported in milliseconds per run;
- stdout redirected to a regular file, never `/dev/null`;
- output and exit status from both project binaries and ripgrep compared with
  GNU grep before timing each workload.

Two complementary views were measured: an A/B pass over the 20 file-based
workloads in the public `generated` profile, and a focused four-tool comparison
of the v0.3 paths.

## Overall v0.3 A/B result

Across the existing 20-case public file profile, v0.3 won 13 lanes and produced
an unweighted 1.039× geometric-mean speedup over v0.2. Summing each lane's
median with equal weight gives a similar 1.044× suite speedup.

| Metric | Result |
|---|---:|
| file workloads | 20 |
| v0.3 wins | 13 |
| geometric-mean speedup | 1.039× (3.9%) |
| equal-weight median-total speedup | 1.044× (4.4%) |
| largest observed per-lane slowdown | 4.5% |

The release-wide result therefore supports an overall gain, not a broad
regression. The largest wins in the public profile were the grouped-prefix ERE
count, literal-alternation count and literal-alternation output paths.

## Focused four-tool medians

The focused workloads cover the v0.3 alternation and dense-prefilter changes,
plus a fixed-literal control:

- fixed literal control: `rare-needle` with count output;
- mixed literal alternation:
  `rare-needle|status=500|route=/api/item/42|latency_us=999` with count output;
- grouped-prefix alternation: `status=(200|500)` with count output;
- dense required-literal prefilter: `status=... latency_us=` with count output;
- grouped-prefix alternation: `status=(500|404)` with numbered line output.

All commands used forced-text mode. GNU-compatible tools used ERE mode for the
regex workloads; ripgrep used its default regex syntax.

| Workload | Mode | Selected lines | zgr v0.3 | zgrep v0.2 | GNU grep | ripgrep | v0.3 vs v0.2 |
|---|---|---:|---:|---:|---:|---:|---:|
| fixed literal control | count | 1,000 | 5.829 | 5.404 | 32.174 | 12.534 | 7.9% slower |
| mixed literal alternation | count | 71,245 | 8.574 | 9.799 | 92.941 | 25.052 | 12.5% faster |
| grouped-prefix alternation | count | 1,000,000 | 8.011 | 10.634 | 65.192 | 40.958 | 24.7% faster |
| dense required-literal prefilter | count | 1,000,000 | 9.448 | 17.392 | 80.573 | 54.190 | 45.7% faster |
| grouped-prefix alternation | output | 58,824 | 14.991 | 31.285 | 61.245 | 34.704 | 52.1% faster |

All four lanes that exercise the v0.3 changes improved over v0.2, by 12.5% to
52.1%, and were faster than GNU grep and ripgrep on this corpus. The
fixed-literal control varied around parity across captures; its 7.9% difference
in this focused run is not treated as a release conclusion.

An exploratory `status=[[:digit:]]{3}` control was excluded from the release
summary after matcher inspection showed that it uses the pre-existing
`AsciiClassSequence` engine, not v0.3's dense-prefilter path. It did run slower
in the v0.3 artifact and remains worth investigating as a separate specialized
engine/code-layout anomaly, but it is neither part of the public profile nor
evidence that the v0.3 dense-prefilter optimization regressed.

This warm-cache sample does not establish results across machines, file
systems, corpus shapes or cold caches.

To replay the same deterministic corpus and controls with the current public
harness (without the archived v0.2 A/B binary):

```sh
bench/generate.sh /tmp/zgrep-v0.3-bench.txt 1000000
BENCH_PROFILE=generated BENCH_BATCHES=9 BENCH_CPUSET=0-15 \
  BENCH_LOCALE=C ZGR=./zig-out/bin/zgr \
  bench/run.sh /tmp/zgrep-v0.3-bench.txt 5
```
