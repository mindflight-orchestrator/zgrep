## Method

- warm cache, `LC_ALL=C`, unrestricted CPU
- 5 runs per tool and case, stdout redirected to a regular file
- every case compared with GNU grep before it was timed; **both `zgr` and
  `zgrc` matched on every generated-profile case**, including dense ERE
  `status=(200|500)` and inner-literal
  `route=/api/item/[[:digit:]]+[[:space:]]+status=500`

```sh
zig build -Doptimize=ReleaseFast
bench/generate.sh /tmp/zgrep-zgr-zgrc-bench.txt 100000
BENCH_BATCHES=1 BENCH_LOCALE=C \
  ZGR=./zig-out/bin/zgr ZGRC=./zig-out/bin/zgrc \
  bench/run.sh /tmp/zgrep-zgr-zgrc-bench.txt 5
```

This is a small ASCII generated-file sample, not the recursive tree profile.
It does not support universal claims across machines, file systems or cold
caches. It also does **not** exercise the experimental GNU gaps listed below.

## Experimental `zgr` GNU gaps

`zgr` (zpcre2 + Zig `locale.zig`) is the default binary. It is **not** a
drop-in for GNU BRE/ERE/locale. `zig build test-zpcre2-gnu` stays experimental
and is not a CI gate. The CLI differential script **passed** against `zgr`;
the failures are regex semantics and UTF-8 locale.

Inventory from the same ReleaseFast `zgr` used in the bench, continuing past
the first mismatch so every case is listed. Status is GNU grep → `zgr`.

### Regex semantics: 27 / 59 failed

POSIX leftmost-longest `-o` (status 0, shorter/wrong span). zpcre2 is
leftmost-first, not GNU longest:

- BRE grouping and alternation `\(a\|ab\)c\?`
- BRE ambiguous backreference `\(a\|aa\)\1`
- ERE nested alternation longest `(a|ab)c?`
- ERE nested suffix longest `a(b|bb)c?`
- ERE multiple-pattern longest span
- ERE interval at expression start `{2}a`

GNU accepts the pattern, zpcre2 rejects it (0 → 2):

- BRE / ERE open lower interval `a\{,2\}` / `a{,2}`
- BRE repetition at expression start `*a`
- ERE unmatched `)` and `a)`
- ERE star / plus / question at expression start
- ERE star at group start `(*a)`

GNU rejects as a fatal error, zpcre2 does not (2 → 1):

- BRE / ERE repetition above the GNU limit `{32768}`

GNU word boundaries missing (`\<` / `\>`, 0 → 1, no match):

- BRE GNU word boundaries
- ERE GNU word boundary

GNU treats PCRE escapes as literals in BRE/ERE; zpcre2 does not:

- `\d` is a literal for GNU, a digit class for `zgr`
- `\n` is a literal for GNU (0 → 1)
- `[\d]` keeps an ordinary backslash for GNU

Other PCRE/GNU syntax splits:

- ERE `(?=a)` is not a lookahead for GNU (no match, 1); zpcre2 matches (0)
- ERE `a+?` is a GNU repeated `+` then literal `?`; zpcre2 parses it as lazy
  (status 0, different spans)

### UTF-8 locale: 60 / 141 failed

The same 20 cases fail in each of `C.utf8`, `en_US.utf8` and `nl_BE.utf8`.
`locale.zig` reads UTF-8 from `LC_*` and uses `std.ascii` for byte classes. It
does not implement libc `wctype` / Unicode case folding / GNU wide word
boundaries.

Unicode case folding (fixed-string and ERE `-i`):

- fixed accented / Greek / whole-line case folding
- ERE accented case folding `^école$`

Unicode / GNU word boundaries:

- fixed accented word boundary, CJK right boundary, CJK word
- ERE GNU accented boundary `\<é\>`
- ERE whole-word alternatives
- recursive fixed ASCII Unicode word boundaries

POSIX / PCRE classes on non-ASCII:

- ERE `[[:upper:]]`, `[[:alpha:]]`, inverted `[[:alpha:]]`, `[[:alpha:]]+` count
- PCRE `\p{L}+`
- Unicode regex witness `[[:alnum:]_]{12}` and the negated class form

Invalid UTF-8 record spans (`.` with `-o`):

- invalid UTF-8 ERE spans
- invalid UTF-8 PCRE spans

Same gap as the C-locale leftmost-longest lane, under UTF-8:

- ASCII hybrid BRE longest span

Locale cases that **did** match GNU in all three UTF-8 locales include ASCII
hybrid ERE count / case-fold / prefilter / longest-span / no-literal, Kelvin /
sharp-s / long-s folding, most invalid-UTF-8 binary summaries, and PCRE ASCII
`\w`. Those are why the generated ASCII bench can stay correctness-gated
while `test-zpcre2-gnu` still fails.

### CLI differential

`tests/differential.sh` against `zgr`: **0 failures**. Color, FIFOs, binary /
NUL, recursion filters and broken-pipe diagnostics matched GNU once the
`grep:` prefix was rewritten to `zgr:`.

## What this bench does not measure

- POSIX leftmost-longest `-o` on ambiguous BRE/ERE
- GNU `\<` / `\>` and Unicode word boundaries
- libc UTF-8 case folding and `[[:alpha:]]` / `[[:upper:]]` on non-ASCII
- GNU-specific syntax GNU accepts or rejects (`{,2}`, unescaped `)`, `{32768}`)
- PCRE constructs accidentally enabled in zpcre2 BRE/ERE (`(?=…)`, `\d`, lazy
  `+?`)
- recursive trees, NUL-delimited corpora, or cold caches

Use `zgrc` when those GNU semantics are required. Use `zgr` when the portable
zpcre2 engine is the product default and the workload stays inside the
generated-profile shape (ASCII literals, simple ERE, counts and line output).
