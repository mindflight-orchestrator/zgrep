# Cursor grep vs zgr

[English](cursor-grep-comparison.md) | [Français](cursor-grep-comparison.fr.md)

Measurement captured on 2026-08-29 at 14:00 CEST on Linux 6.8.0-138-generic
x86_64, with an Intel Core i9-13900KF (32 logical CPUs), Zig 0.16.0, GNU grep
3.11 and Cursor-bundled ripgrep 15.1.0-cursor5 (rev `c3e3c2f7ec`). The file
corpus was generated by `bench/generate.sh` with 100,000 records: 9,378,980
bytes and SHA-256
`1dcecb7edb774134592782760c18b6d8f09fc91b2cc9f6463bfd85cc77b75c45`.

This is a small, warm-cache sample of how Cursor's agent Grep behaves next to
`zgr`. It does not support universal claims across machines, file systems or
cold caches.

## Compared artifacts

- Cursor Grep: the agent search tool, a JSON wrapper around a bundled
  `rg`. The timed binary is that bundled ripgrep, not the agent RPC layer.
- Cursor `rg` 15.1.0-cursor5, statically linked, 5,396,392 bytes, features
  `+pcre2`, PCRE2 10.45 with JIT. SIMD at runtime: SSE2, SSSE3, AVX2.
- `zgr` 0.3.1 (zpcre2 default), ReleaseFast from this tree at `8769176`,
  dynamically linked to libc, 831,688 bytes:
  `3797160790268324f309dc73839bf7b0edc6b0917bd4f145335027b75f2d9020`
- `zgrc` 0.3.1 (C PCRE2 JIT GNU-compat), 461,720 bytes:
  `239e37ffe76c0bffec11e61c59bc59eb483d55611f4376cea7d782b16227171f`
- GNU grep 3.11

## Method

- warm page cache, `LC_ALL=C`, unrestricted CPU
- tree cases: median of 9 runs; file cases: median of 5 runs
- stdout redirected to a regular file, never `/dev/null`
- Cursor `rg` used its default ignore rules (gitignore, skip hidden, skip
  binary) unless noted
- fair `zgr` / GNU grep tree runs passed
  `--exclude-dir=.git --exclude-dir=.zig-cache --exclude-dir=zig-out`
- GNU-compatible tools used `-F` / `-E` / `-P` to match each ripgrep mode;
  ripgrep used its default regex syntax except for explicit `-P`

Replay:

```sh
zig build -Doptimize=ReleaseFast
BENCH_BATCHES=1 TREE_PATTERN=Matcher \
  bench/run-cursor-rg.sh . 9
```

Override the ripgrep binary with `CURSOR_RG`. If Cursor is not installed, the
script uses `rg` from `PATH`. Set `CORPUS` to reuse a generated file, or let
the script call `bench/generate.sh` (100,000 records by default).

```sh
bench/generate.sh /tmp/zgrep-cursor-rg-bench.txt 100000
CORPUS=/tmp/zgrep-cursor-rg-bench.txt BENCH_BATCHES=1 \
  bench/run-cursor-rg.sh . 5
```

## What differs besides speed

Cursor's agent Grep is built to hand an agent source hits in a git checkout.
`zgr` is built to follow GNU grep. The important defaults:

| Capability | Cursor Grep tool | Cursor `rg` CLI | `zgr` |
|---|---|---|---|
| Default syntax | Rust regex | Rust regex | BRE (`-E` / `-F` / `-P`) |
| Recursion | always | default | only with `-r` / `-R` |
| gitignore / hidden | on, not optional in the tool schema | on, overridable | off |
| Binary files | skipped | skipped | GNU `binary` / `text` / `-I` / `-a` |
| Result cap | a few thousand lines | none | none |
| `-F` / `-P` | not in the tool schema | yes | yes |
| Type / glob | `glob` and `type` | rg globs and types | `--include` / `--exclude` / `--exclude-dir` |

On this repository that gap is larger than the matcher. The tree is about
2.4 MiB of source beside a 1.3 GiB `.zig-cache`. Cursor `rg --files` walked 36
paths. `find` walked 780. `zgr -r` without excludes searched the cache.

## Tree result

Pattern `Matcher` with line numbers, this repository as of the capture.

| Tool | Median | Matching files | Matching lines | What it walked |
|---|---:|---:|---:|---|
| cursor rg (default) | 3.568 ms | 5 | 137 | 36 gitignore-visible files |
| zgr `-r`, caches excluded | 1.774 ms | 5 | 137 | 133 files outside git/cache/out |
| GNU grep `-r`, same excludes | 3.145 ms | 5 | 137 | same 133 files |
| zgr `-r` (GNU recursive) | 51.004 ms | 62 | 137 | 780 files, including 1.3 GiB cache |

`src/` only, no ignore rules in play:

| Tool | Median |
|---|---:|
| zgr `-r src` | 0.846 ms |
| GNU grep `-r src` | 1.153 ms |
| cursor rg `src` | 3.407 ms |

On a tiny tree, process startup and ignore-rule evaluation dominate Cursor
`rg`. The 14× gap on the full recursive run is `zgr` reading the Zig cache,
not a slower matcher.

## Generated-file result

Corpus `/tmp/zgrep-zpcre2-bench.txt`, 100,000 lines. Times are milliseconds
per run. Lower is better. GNU grep has no `-P` on this host.

| Workload | cursor rg | zgr | zgrc | GNU grep | Winner |
|---|---:|---:|---:|---:|---|
| literal miss `-c` | 2.355 | 2.896 | 2.877 | 3.378 | cursor rg |
| rare literal `-c` | 2.244 | 2.043 | 2.018 | 4.463 | zgrc |
| word literal `-cw` | 2.634 | 1.792 | 1.919 | 4.235 | zgr |
| case-insensitive `-ci` | 3.840 | 2.111 | 2.079 | 4.238 | zgrc |
| ERE `status=(200\|500)` `-c` | 5.493 | 3.396 | 3.098 | 9.538 | zgrc |
| inner-literal ERE `-c` | 6.325 | 2.805 | 3.390 | 9.298 | zgr |
| literal output `-n` | 2.372 | 2.117 | 1.886 | 4.740 | zgrc |
| PCRE `latency_us=\d+` `-c` | 7.085 | 6.730 | 3.253 | n/a | zgrc |

Match counts agreed where compared: 100 `rare-needle` hits and 100,000
`status=(200|500)` hits.

On a named file, `zgr` / `zgrc` won every lane except the literal miss.
`zgrc` was fastest on the dense PCRE count, which is C PCRE2 JIT rather than
zpcre2.

## Dialect

Cursor `rg` uses Rust regex, so `|` is alternation. `zgr` defaults to BRE, so
`|` is a literal pipe. Searching `src/` for `error|warning`:

| Tool | Hits |
|---|---:|
| cursor rg | 203 |
| zgr (BRE) | 1 |
| zgr `-E` | 203 |

Pass `-E` (or `-F` / `-P`) before treating a ripgrep pattern as a `zgr`
pattern.

## Reading the result

Cursor grep is the better default inside a git checkout: it searches the 36
files an agent cares about and never opens `.zig-cache`. `zgr` is the better
GNU-shaped scanner on a named file or a tree whose junk you have already
excluded. Point `zgr -r` at this repository without `--exclude-dir` and it
will correctly, and slowly, search the cache.
